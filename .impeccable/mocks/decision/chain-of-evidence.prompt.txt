Use case: ui-mockup
Asset type: 1536x1024 landscape desktop web application comp for Pickle Spec Studio

Primary request: Recraft the full visual world as “Chain of Evidence”, a forensic chain-of-custody instrument where every failure is a case whose causal chain can be proven, not guessed. Create a high-fidelity, shippable product interface—not concept art, not a marketing page.

Scene/backdrop: Full browser viewport of an active local QA investigation workspace. No device frame. Continuous dense application shell with no floating cards in empty space.

Subject and structure:
- Product name at top left: “Pickle Spec”.
- Compact case index or breadcrumb in the left rail/top: Specification “Checkout” → Scenario “Pay for the order” → target “chrome”.
- Main header spells status “failed”; show execution mode “adaptive”, Cache outcome “uncacheable”, inference count “0”.
- Tabs exactly, in this order: “Overview”, “Timeline”, “Artifacts”, “Diagnostics”.
- Center causal timeline with three sequential steps: a passed Given step, a passed When step, then the failed step “Then payment is captured”. The failed step expands into a chain showing resolved action “Click pay on chrome”, then Diagnostic entry “Payment was declined”, then Test artifact “failure.png”.
- Large evidence viewer at right containing a realistic ecommerce checkout failure screenshot: an order checkout form with payment declined inline, clearly a captured test image rather than another dashboard.
- Fixed evidence slots with stable geometry; include one explicit empty slot labeled “not-retained”.
- Dense metadata aligned tabularly, compact filters for state/evidence/target, and a clear action button “Inspect result”.
- Designed for active QA investigation and causal proof, with state changes never moving controls.

Style/medium: Realistic high-fidelity desktop developer-tool UI. “Chain of Evidence” visual world inspired by archival case stock, glassine evidence sleeves, graphite annotations, and restrained rubber seals, translated into practical modern UI surfaces—not literal scrapbook decoration and never a cliché red-string board.

Color palette: carbon #17191B application chrome; evidence paper #E8E4DA; seal red #A8322A for spelled failure state; lab green #52675D for spelled passed state; neutral #AAA397. WCAG-minded contrast.

Materials/textures: Very subtle evidence-paper fibers and glassine translucency inside evidence regions only; precise graphite rules and case-number annotations; restrained seal marks. Flat, stable application layout.

Typography: Highly legible workhorse sans for UI; restrained mono for identifiers, timestamps, counts, and target names; practical developer-tool density; dense measurements align tabularly.

Text (verbatim): “Pickle Spec”, “Checkout”, “Pay for the order”, “chrome”, “failed”, “adaptive”, “uncacheable”, “0”, “Overview”, “Timeline”, “Artifacts”, “Diagnostics”, “Then payment is captured”, “Payment was declined”, “Click pay on chrome”, “failure.png”, “not-retained”, “Inspect result”.

Constraints: Render every required key label verbatim and at readable size. Spell all states; never rely on color alone. No cards floating in empty space. No dashboard summary-card grid. No neon, glow, glassmorphism, marketing copy, invented product features, logos, watermark, device frame, tiny illegible filler text, or gibberish. No red-string-board imagery. Landscape full browser viewport, polished enough to hand to product engineering.
