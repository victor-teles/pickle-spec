---
title: Quick start for web
description: Run a Gherkin Scenario against local Chrome.
---

This tutorial runs one Specification against [Example Domain](https://example.com). You need Bun 1.4.2 or newer, local Chrome, and an Anthropic API key. You can install and invoke Pickle with npm, pnpm, Yarn, or Bun; choose a tab in the command examples below. Bun must be installed because it runs the CLI.

<Steps>
<Step>

### Install and initialize Pickle Spec

From your application repository, run:

```npm
npm install --save-dev @pickle-spec/cli
npx pickle init
mkdir -p features
```

`pickle init` creates a configuration shell and a custom-adapter example. This tutorial uses the built-in web adapter, so delete the generated `pickle.extensions.ts` file.

</Step>
<Step>

### Configure the web target

Replace `pickle.config.jsonc` with this file:

<include cwd lang="jsonc" meta='title="pickle.config.jsonc"'>
  examples/web-quick-start/pickle.config.jsonc
</include>

The named `web` profile selects the built-in web adapter. `applicationRevision` lets a later matching run use the Execution cache.

</Step>
<Step>

### Add the Specification

Create `features/example.feature`:

<include cwd lang="gherkin" meta='title="features/example.feature"'>
  examples/web-quick-start/features/example.feature
</include>

The Feature state is required. Pickle derives durable IDs unless you add explicit `@pickle:id:*` tags.

</Step>
<Step>

### Add the model key

Create `.env` in your project root:

```dotenv
ANTHROPIC_API_KEY=your-api-key
```

Bun loads `.env` automatically. Do not commit API keys.

</Step>
<Step>

### Check and run the project

```npm
npx pickle check
npx pickle run --profile web
```

`pickle check` validates the configuration, Gherkin, Feature state, and identity metadata without opening Chrome. The run opens a clean browser session and reports the Scenario result in the terminal.

</Step>
</Steps>
